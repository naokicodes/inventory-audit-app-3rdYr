# Inventory Audit App

A local meat-inventory audit tool covering 3 restaurants. See `docs/` for
the full spec — start with `docs/scope.md` if you're new to this project.

If you are joining as a collaborator, read `docs/engineer-role.md` before
you change anything. It defines what you may fix on your own and what has
to wait for an architect.

## Requirements
- Node.js 22.13.0 or newer (this project uses Node's built-in SQLite
  support — see `docs/tech-stack.md` for why).
- Git - Claude Code — the CLI used for implementation work. Installed globally
  via npm; see `docs/engineer-role.md` for how work is scoped.
- graphify — the knowledge-graph tool this project uses for code
  navigation. `CLAUDE.md` instructs Claude Code to query it *first* on any
  codebase question, so without it your very first worker action fails on
  a command you don't have.

If you ran `setup-dev-environment.bat`, all four are already handled.

## First-time setup on a new computer

1. If this is a fresh machine with nothing installed yet, run
   `setup-dev-environment.bat` first — it installs Git, Node.js, VS Code,
   Claude Code, and graphify.

   ⚠ Some public/shared computers restrict installing software or wipe
   changes on restart — check this before relying on that machine for
   ongoing work.

2. Clone this repo:
   ```
   git clone https://github.com/naokicodes/inventory-audit-app-3rdYr.git
   cd inventory-audit-app-3rdYr
   ```

3. Install dependencies (one-time per machine — see note below):
   ```
   npm install
   ```

4. Install the graphify git hook — **once per clone, not once per
   machine**:
   ```
   graphify hook install
   ```
   This one is easy to skip and the failure is delayed and confusing.
   `.gitattributes` (committed, shared) declares a merge driver for
   `graphify-out/graph.json`, but the driver logic lives in local
   `.git/config`, which never travels with a clone. Skip this and git
   either errors on an unknown merge driver or silently mangles the graph
   the first time you merge a branch. If you are working on branches and
   opening pull requests, you *will* hit this.

5. Run the app:
   ```
   npm run dev
   ```
   Open the URL it prints (e.g. `http://localhost:3000`) in your browser.

## `npm install` — when you actually need to run it
- **Once**, right after cloning onto a machine that's never had this
  project's dependencies installed.
- Again, only if `package.json` changes (a new dependency gets added).
- **NOT** every time you sit down to work — `npm run dev` alone is enough
  for a normal work session.

## Running the tests
There is no test runner script. Run each file directly:
```
node server/routes/commissary.test.js
```
The full suite is 16 files — everything matching `*.test.js` under
`server/`. Two are easy to miss because they sit outside
`server/routes/` and `server/engines/`: `server/db/activityLog.test.js`
and `server/db/migrate.test.js`.

`commands.test.js` and `sales.test.js` print a SQLite
`ExperimentalWarning` *after* their count line — read the count, not the
last line of output.

A green suite is necessary but not sufficient on UI work. Several real
bugs have shipped past a fully green suite; anything touching `public/`
needs a browser click-through as well.

## Project structure
```
docs/          <- the rules/spec docs — read these before changing anything
server/        <- backend (Express + SQLite)
  db/          <- database connection + schema (SQLite file lives here, gitignored)
  engines/     <- calculation logic (audit engine, recipe engine, etc.)
  routes/      <- API endpoints
  **/*.test.js <- the automated tests live next to the code they cover
public/        <- frontend (plain HTML/CSS/JS, no build step)
uploads/       <- photo attachments (gitignored — local data only, never committed)
graphify-out/  <- committed knowledge graph — queried via the CLI, never read raw
```

## What NEVER gets committed (enforced via `.gitignore`)
- The SQLite database file (`*.db`) — this is real business data, stays
  local only.
- `/uploads/` — staff photo attachments, same reasoning.
- `.env` — secrets (API keys, etc.), once that exists.
- `node_modules/` — regenerated by `npm install`, not source code.

This repo is **public**. Never put real supplier names, staff names, live
yield figures, or photos into code, docs, commit messages, issues, or
pull requests.

## Verifying your environment

One command proves the whole setup. From the repo root, in PowerShell:

```
Get-ChildItem -Path server -Recurse -Filter *.test.js | ForEach-Object { $o = node $_.FullName 2>&1 | Select-String "passed" | Select-Object -Last 1; "$($_.Name) :: $o" }
```

You should get 16 lines and **325 passed, 0 failed** in total, with
`commissary.test.js` the largest at 94. Anything else means the
environment is wrong, not the app.

Verified working on Node 22 and Node 24.19.0 — identical results on both,
so `OpenJS.NodeJS.LTS` resolving to a newer major is fine.

## Troubleshooting a fresh Windows setup

All six of these were hit in one real setup session. None are app bugs;
they are all environment.

**`npm : File ...\npm.ps1 cannot be loaded because running scripts is
disabled`**
PowerShell blocks the `.ps1` shim. Either allow scripts for this window
only —
```
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```
— or sidestep it entirely by calling the `.cmd` directly: `npm.cmd`,
`claude.cmd`, `graphify.cmd`. Prefer `-Scope Process` on a shared
machine; it dies with the window and leaves nothing relaxed behind you.

**The execution-policy fix stopped working**
It is process-scoped, so it does not survive a new terminal. Re-run it
each session.

**`fatal: could not create work tree dir ... Permission denied`**
The clone path isn't writable. Use `cd $env:TEMP` and clone there, or
create `C:\Temp`. Treat anything in `$env:TEMP` as disposable — shared
machines often wipe it on reboot.

**`setup-dev-environment.bat` step 5 fails with "not recognized"**
Expected on a first run: winget installed Git/Node/uv but this window's
PATH predates them. Close the window, open a new one, run the script
again — it skips what's already installed. To fix just that step without
a full re-run:
```
npm.cmd install -g --allow-scripts=@anthropic-ai/claude-code @anthropic-ai/claude-code
```
```
uv tool install graphifyy
```

**Claude Code installed but `claude` misbehaves**
Recent npm blocks install scripts by default and prints an
`allow-scripts` warning, so the package lands but its postinstall never
runs. Reinstall with the `--allow-scripts` form above.

**`graphify` not recognized even after `uv tool update-shell` says PATH
is updated**
A PATH change does not reach VS Code's integrated terminal until **VS
Code itself** restarts — closing the terminal panel is not enough. Fix
the current window with:
```
$env:PATH = "$env:USERPROFILE\.local\bin;$env:PATH"
```
or close VS Code entirely and reopen it.
